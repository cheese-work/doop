## How to read this file

- A row is one fork feature. `Upstream v0.15.0 coverage` is one of `none`, `partial <upstream commit or PR>`, or `overlaps <upstream commit or PR>`.
  `none` means that no behavior-equivalent upstream code was found at `v0.15.0`.
  `partial` and `overlaps` name the upstream change, and the recommendation says what the fork still adds.
- The row ID is a letter and two digits. `scripts/fork-sync-guard.mjs` in the multica fork reads this layout: a row starts with `| <ID> `, and the backtick-quoted paths after `Source:` are the protected paths.
  A path ending in `/` protects every file under it. A name without `/` uses the directory of the path before it, so every path below is written in full.
- Fork PR numbers are in `cheese-work/doop`. CHE numbers are Multica issues.
- Column `Depends on`: `hard` means the row cannot be kept without the named row; `soft` means they share code but each works alone.
